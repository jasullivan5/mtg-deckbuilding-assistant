# Contribution model validation

**Historical vocabulary study.** The original four-/five-role protocols, recommendations, sources and verification below are retained as evidence. They are not the current role specification or an implementation queue. The [2026-11-09 six-role direction](OBJECTIVE_MODEL.md#working-objective-relative-roles) supersedes the vocabulary recommendations while retaining their open mechanical questions. Prototype Lab below names the historical review context; a separate mandatory role is no longer required. The current Primer identifies this distinction.

## Comparison protocol

The comparison unit is a single contribution to a stated objective requirement. Describe the capability, its causal connection, and its prerequisites before assigning labels. Keep objective admission and deck value separate.

Compare the two models against three checks:

1. Can the reader tell what changes, what starts the effect, and when any prerequisite or magnitude is evaluated?
2. Does an extra role explain an additional contribution, or repeat a dependency already required to describe the same mechanic?
3. Can the model preserve two causally linked roles, such as responding to a death and thereby providing a resource, without implying two independent actions?

For the four-role model, record separately which objects qualify, continuous quantity inputs, branches checked at resolution, and earlier-event history. A response means the event starts an ability. A spell that checks event history on resolution is tested against that boundary. In the five-role comparison, try Leverage State wherever a meaningful advantage varies with a threshold, count or established history. An ordinary recipient filter alone is insufficient. Record ambiguous role boundaries and keep the same mechanical facts for both interpretations.

Development set: Reassembling Skeleton, Viscera Seer, Pitiless Plunderer, Walking Corpse, Murder, Exploration, Lotus Cobra, Scute Swarm, Goblin Chieftain and Cranial Plating. Reserve **Goblin Piledriver** and **Tragic Slip** for evaluation against these criteria without changing them. These are purposive, known-card controls held out from rule development, with no claim of blinding or statistical generalization.

## Initial assessment

**Initial recommendation: four roles with separate state-dependency semantics.** Provide distinguishes an output such as mana or Treasure. Facilitate explains enabling a death or land play. Respond to Event identifies what starts an ability. Modify describes changing an existing characteristic, permission or effect. In this sample, Leverage State draws attention to an investment in board state, but it groups three different mechanisms: continuous quantity, a resolution-time quantity, and a branch selected at resolution. The added label does not replace any of those distinctions. Chieftain’s recipient scope still depends on the board, even though the per-creature bonus is fixed.

The two held-out controls fit the event/history distinction without changing the protocol. Piledriver also exposes a possible fidelity edge: native code subtracts one from the controlled attacking-Goblin count, which can undercount if Piledriver stops being a Goblin while attacking and the trigger still resolves. This is a source/code discrepancy hypothesis without an executed scenario. Tragic Slip only checks prior death history when the cast spell resolves. The objective recognizes death-enhanced removal, so an accepted relationship alone cannot identify a trigger.

Overlap helps when it preserves causality, as in Plunderer’s death → trigger → Treasure. It obscures the action when Facilitate and Modify both describe Exploration’s permission increase. Both models leave that boundary awkward. Both also need a distinctiveness rule to separate Skeleton from an ordinary creature body, and neither predicts Murder’s policy exclusion or contextual deck value. Keep those failures visible.

## What existing code can support

- The native action records and shared movement facts can anchor Skeleton’s graveyard return. The reanimation predicate can recognize that return. Sustained death fuel still needs recurring costs and a separately supported sacrifice route. The death query does not currently compose those relationships.
- Sacrifice and destroy are available in the death projection, which separates compatibility from objective admission. Tragic Slip’s positive history condition is supported in that bounded projection. The token query and reanimation query instead share fact predicates for controller, zone, type and constraints. Reuse the extracted action identity, branch and facts where available. Avoid using a matching effect from another ability on the same card.
- Plunderer and Swarm have native triggers with nested effects. Shared token facts describe outputs and can retain action/branch references. A payoff needs a join to the exact trigger with timing, object identity, controller and token restrictions intact. A copied Swarm can change later trigger capacity without changing the count made per resolution. Unrecognized predicates or lost effect context need an explicit unknown.
- Cobra’s mana output and Exploration’s land-play permission are native. The extractor skips standalone mana/draw leaves in the bounded death analysis and leaves most static effects uninterpreted. No general mana, land-entry or combat contribution query consumes these actions. The Chieftain and Plating printings had no authored definitions in the inspected baseline, so they are source-only cases. Piledriver is authored but raises a fidelity question separate from query coverage.

A subsequent bounded engineering experiment could correlate a native death trigger with output in the same ability for Plunderer, Doomed Dissenter and Grim Haruspex. Check controller and token filters, self versus another creature, unrelated abilities and unsupported branches against frozen source expectations. This would test causal linking without implementing a taxonomy. It remains a separate Product Studio decision.

## Follow-up: state access and complementary capabilities

The initial protocol underweighted binary access. Under the clarified definition, **revise the boundary**. Preserve Leverage State as a visible, directional relationship from an established state to a capability. Keep the other four roles as descriptions of what the ability supplies or does. Product Studio can decide whether that relationship merits a fifth label in the experience. The first 12 examples and the two original held-out controls retain their original research scope. The follow-up adds three examples for clarification, with no new held-out or population claim.

| Case | Ability and incoming relationship | What the competing models need to explain |
| --- | --- | --- |
| Flamewake Phoenix | A power-4 creature under your control at the beginning of your combat and again at resolution enables the graveyard return, with optional red payment. Power 8 does not improve the return. | Respond to Event and Provide describe the trigger and resulting creature. Leverage State highlights the binary access supplied by the board. Four roles can show the same access if the threshold and timing are structured and exposed as a relationship. |
| Zulaport Cutthroat | Its own death or another controlled creature’s death starts the same trigger. Each opponent loses life and its controller gains life. | A death strategy supplies the incoming event. A life-gain strategy values the outgoing effect. Switching objectives leaves the trigger, controller and output intact. |
| Chieftain, Plating and Coat of Arms | Chieftain applies a fixed bonus to other controlled Goblins. Plating counts controlled artifacts continuously for one equipped creature. Coat counts other creatures sharing a type separately for each recipient, across controllers. | A wide Goblin board benefits even from a fixed bonus. Modify explains the effect. A state relationship explains why a producer of matching bodies or artifacts could complement it. The relationship must carry recipients and controller scope, including possible opposing benefit from Coat. |
| Scute Swarm | Land entry starts the trigger. Six controlled lands at resolution select the copy branch. | Both the event and state are useful dependencies. The threshold changes output identity and later trigger capacity, while each individual trigger still supplies one token under ordinary resolution. |

**What the fifth role adds.** A visible label invites a useful discovery question: what can this strategy establish that makes an otherwise conditional ability available or stronger? Event and state inputs can both have suppliers. An event is a qualifying occurrence that can initiate an ability. A state is a predicate that can enable a trigger, select its output or modify an ongoing effect, evaluated at specific times. Keeping Respond to Event as a role highlights the triggered causal structure. Giving Leverage State similar visibility makes sense for strategy research. The two labels still require different mechanical records.

**What four roles would need to match it.** Retain the required state, affected object, controller, quantity or threshold, evaluation time, duration, capability and resulting effect, then correlate them with what a strategy can actually produce. For example, Chieftain can raise another controlled 3-power Goblin to 4 before combat, potentially supplying Phoenix's threshold. A boost that begins after attackers are declared is too late. A later removal can make the threshold fail again on resolution. For Plating, retaining Treasure supplies one artifact, while sacrificing that same Treasure for mana removes it from the count. These are illustrated joins, with no gameplay run and no implemented discovery of the combination. Four roles with inspectable, joinable dependencies can express the same complementary relationships. Four roles with only a text prerequisite can bury them. A fifth label without the dependency data cannot establish them.

**Boundary and negative controls.** Keep every ordinary cost, timing rule and zone requirement in the mechanic. Reserve the distinctive state relationship for cases where the selected strategy plausibly supplies or maintains the relevant predicate and doing so changes access, output or effectiveness. Paying mana or merely having a permanent on the battlefield is insufficient evidence of such a fit on its own. Red mana could matter in a narrower resource strategy that actually supplies it. Provide supplies the resource, Facilitate helps establish the state or event, Leverage State uses the resulting state, and Modify describes the change. One ability can span these, and Exploration's permission change remains ambiguous between Facilitate and Modify. Distinctiveness and current objective admission remain separate judgments.

**Prototype Lab.** In **Events versus states**, compare Flamewake Phoenix to Cranial Plating and Coat of Arms. Ask which card or strategy supplies the state, whether it arrives in time, and who benefits. Then switch Zulaport Cutthroat between **Creature-death lens** and **Life-gain lens**. The requirement and explanation change while the ability stays fixed. Compare Scute Swarm's resolution threshold to Phoenix's two checkpoints before opening the assessment.

**Evidence.** The new Phoenix case reuses the retained FRF #100 source and the M3.2 reanimation change. Its source/native threshold is also corroborated by the [Foundations release notes](https://magic.wizards.com/en/news/feature/foundations-release-notes). Cutthroat BFZ #126 and Coat LCC #108 are bound to exact source snapshots. Native Cutthroat and Phoenix were inspected at engine `03869c08665bf476a8b40dacbfbcd501c54a33bd`. Coat has no located native definition at that revision and is source-only. Its controller and shared-type scope follow the [Lost Caverns of Ixalan release notes](https://magic.wizards.com/en/news/feature/the-lost-caverns-of-ixalan-release-notes). The follow-up expands the conceptual examples to 15 exact printings. It creates no discovery or execution evidence, and the original measurements and findings remain historical.

## Final refinement: atomic objectives and future composition

**Working hypothesis.** Give each objective one mechanically precise success criterion, then investigate whether strategies can compose those criteria through supported mechanical relationships. A narrow definition gives discovery a stable question and gives reviewers a way to see exactly why one objective might help another. It leaves room for several kinds of contribution to the same objective. The existing Explorer queries remain the evidence baseline for this proposal.

| Proposed objective kind | Defining criterion | Related mechanics to track separately |
| --- | --- | --- |
| Event | **My nontoken creatures die.** A nontoken creature I controlled immediately before it left the battlefield moves to a graveyard. A plan can seek repeated occurrences. | Creature supply and a legal sacrifice are possible inputs. Zulaport Cutthroat can respond to a qualifying death even though its outputs are life gain and opponent life loss. A death can also reduce battlefield population, update event history, and change a graveyard's contents. |
| State | **I control at least six lands.** Count lands I control at the relevant checkpoint. A plan can seek to establish or maintain that condition. | Land-play permission and land supply can help establish the state. Other effects can put lands onto the battlefield. Scute Swarm separately needs a land entry to trigger and checks the six-land state as it resolves. Reaching six lands alone supplies no trigger. |

Prerequisites say what a particular route needs. Consequences say what an occurrence changes. A connection to another objective needs its own conditions and evidence. A controlled creature can die into another player's graveyard if that player owns it. An animated noncreature card can die as a creature and count as a different card type in the graveyard. A replacement that sends a creature to exile can remove it from the battlefield without a death. These differences matter when connecting the death event to **I have at least one creature card in my graveyard**. They give no general reason to include cards that benefit from graveyard size in the death objective. See [current death coverage](OBJECTIVE_COVERAGE.md), the [Wizards rules glossary](https://magic.wizards.com/en/keyword-glossary), and [finality counter rulings](https://magic.wizards.com/en/news/feature/duskmourn-house-of-horror-release-notes).

**Contribution vocabulary.** Provide, Facilitate, Respond to Event, Leverage State, and Modify explain relationships to a criterion. Their usefulness and number remain open. Exploration modifies land-play permission and can facilitate an additional land entry if a land and a legal play are available. Establishing a state can result from those kinds of contributions, separately or together. There is no present case for a sixth Establish State role. The earlier role assessment remains evidence about how to explain contributions, with objective boundaries and composition now the research priority.

**Open boundary for modification.** A Goblin combat plan could seek a state such as three Goblin creatures I control with at least eight total power at the beginning of my combat, and an event such as a Goblin I control dealing combat damage to an opponent. A lord can help reach the state and improve the attack. The state alone cannot distinguish making existing creatures larger from adding already-large creatures. The damage event alone cannot explain how the damage was improved. Test whether an explicit before-and-after relationship for the same recipients within a timing window can preserve the intent of *increase my creatures' power*. Whether that needs a separate effect objective remains open.

**Victory Path.** A future plan-level review could identify at least one credible, provisional route from development objectives through conversion to a win. Examples include combat damage, cumulative opponent life loss, poison, exhausting a library followed by an attempted draw from it, or an explicit alternate-win condition. More resources or repeated events can advance internal objectives without improving the position against opponents or supplying a route to win. Victory Path belongs to plan-level research. It adds no atomic objective kind or current deck requirement.

**One proposed next experiment.** In a read-only worksheet, compare grouping death and graveyard benefits under one broad death objective with two atomic criteria, *my nontoken creatures die* and *I have at least one creature card in my graveyard*, plus a conditional link between them. Freeze expected results for a Viscera Seer sacrifice of an owned creature card, an opponent-owned creature I control, a token, and a Wolfbat carrying a finality counter. Start each case with no creature cards in my graveyard. The owned creature card should satisfy the event and establish the state if it reaches and remains in my graveyard at the observation point. The opponent-owned creature can satisfy only the event. The token can trigger broader death payoffs but satisfies neither criterion, and the finality replacement can prevent both. Reuse the recorded Seer sacrifice in M3.1 and Wolfbat return and restriction in M3.2 as evidence for their individual mechanics. Inspect the native action and extracted zone, object, owner, controller and branch information to see which links it can support. Keep unresolved ownership, replacement or destination explicit. Compare whether the separate criteria preserve direct event responses and explain each join or failed join without widening the death search. These are proposed cases with no observed combined execution. Product Studio decides whether to run the experiment.

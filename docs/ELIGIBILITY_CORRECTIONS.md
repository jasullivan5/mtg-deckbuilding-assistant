# Reviewed Commander eligibility

Catalog.eligibility is the application-owned effective view of full color identity and Commander format legality. Discovery, commander inspection, conventional identity/format search projections and external coverage use it. Native CardDefinition objects, scripts and original metadata remain intact for diagnosis.

The reviewed data is packaged in [eligibility/phase29.json](../cli/src/main/resources/eligibility/phase29.json). Its dated sources and original revision identify approval evidence, not a dependency pin. The runtime validates the bounded approved records against current identity associations, expected/approved values, source observations and native fingerprints. Proposals do not apply. Changed identifying data, conflicting claims, unsupported values or unreviewed mechanical changes fail rather than partially applying a plan.

Full identity includes all relevant faces/restrictions and native mana/color indicators. Color compatibility cannot legalize a banned or nonlegal card. A value already corrected upstream can be recognized while preserving the original approval record; unrelated eligibility fields require their own review. Source versions and native changes must be reconciled explicitly rather than accepted by branch name alone.

A new correction needs confident physical identity, dated authoritative source evidence, full expected/approved field values, reviewed native bindings and tests for affected consumers and rejection cases. Matching names alone do not authorize changes. Keep format legality, identity association, mechanics and translation assurance separate.

Historical seven-card investigations, old snapshot downloads and measured phase counts are in the export. The packaged current plan and its regression tests remain in the active repository.

# Current translation assurance procedure

Discovery, faithful translation, native execution and strategic usefulness are different claims. The application exposes representation, source fidelity, recorded execution and qualification separately. Inherited engine definitions receive no silent application certification.

The packaged ledger is src/main/resources/translation-assurance.json. Its source/requirements/test references bind exact retained reference files and hashes. Current source-led/author tests support provisional research; independent qualification requires explicit separate human approval of the exact evidence bundle. Runtime checks definition/engine compatibility and recorded bindings; tests check the referenced files. Neither fetches live Oracle text as an implicit approval.

## Source-first review

1. Confirm physical card/face identity, authoritative Oracle text and rulings. Archive compact source evidence with dated provenance.
2. Write stable source-derived requirements before reviewing implementation explanations. Preserve costs/effects, optional/mandatory actions, owner/controller/source/host, zones, target/choice, timing and sequential relationships.
3. Compare requirements to native relationships. Separate structural inspection from behavior needing execution.
4. Run bounded adversarial scenarios and meaningful positive/negative controls. Record observed state/events, failures, harness issues and untested gaps separately.
5. Preserve first failures and concern history. Do not redefine expectations to pass or treat a successful scenario as whole-card certification.
6. Bind the decision to exact source, requirements, definition, test evidence and engine revision. Independent qualification requires a distinct human reviewer and explicit approval, never automatic promotion from automation.

## Existing concerns and admission

Tatterkite retains its CONFIRMED material concern and BLOCKED qualification. An engine correction or merge alone does not close it; resolution needs a separately reviewed evidence-bound record. Other application translation records remain provisional without independent approval. Cleanup moves no ledger field, referenced byte, concern or qualification.

Extensions.validate checks provenance, unique physical identities, representable metadata and native validation errors. DefinitionReview records scenario references and limitations; registration does not execute those scenarios or adjudicate Oracle fidelity. Provisional research definitions remain accessible; qualification does not replace Commander eligibility or objective interpretation.

Qualification is computed from the exact bundle. Missing/stale evidence remains unreviewed or untested. Open material discrepancy, incomplete representation or observed execution failure blocks qualification. Changed evidence can withdraw prior approval. Independent approval fixtures are isolated tests, never real card approvals.

The historical experiments are exported; hash-bound records still required by this ledger remain in [active reference evidence](../src/test/resources/README.md). See [authoring](COMMANDER_AUTHORING.md) and [repository layout](REPOSITORY_LAYOUT.md).

# Development environment

Use the application repository for assistant work and [our Argentum fork](https://github.com/jasullivan5/argentum-engine) for native engine/SDK work. The application fetches the exact [ARGENTUM_COMMIT](../ARGENTUM_COMMIT) into a separate clean `argentum/` dependency. Fork `app-stable` is the engine development base; `main` tracks upstream. Neither floating tip is a dependency specification.

Required tools: Git, JDK 21 including `javac`, Bash and Python 3. Set `JAVA_HOME` and its `bin` on `PATH`. [README](../README.md#setup-and-verification) gives Bash and PowerShell setup and test entry points. Use `dev`/`dev.ps1`; engine-owned Gradle settings integrate the external application module. Setup needs public GitHub, Gradle distribution, Maven Central and Plugin Portal access. A supported proxy/public truststore may be configured externally; never disable TLS or commit credentials.

Setup validates/reuses the exact clean pin and refuses wrong revisions, modified source and unrelated origins. It migrates only recognized legacy upstream origins. An adopted-pin transition needs an explicit clean dependency checkout change after checking its linked worktrees/history; then rerun setup. A temporary isolated checkout is appropriate when old/new revisions must coexist. Do not change guards or remove shared Git storage to make setup succeed.

Ordinary development uses branches in the primary application and engine checkouts; a new branch alone is not a reason for a worktree. Keep the pinned dependency detached and clean. Preserve evidence and check active consumers/untracked/unpushed work before removing ended temporary worktrees with Git's normal non-force operation. Independent nested clones require separate review. See [workflow](../README.md#everyday-workflow-and-documentation-ownership).

Gradle uses its normal dependency/build caches. `GRADLE_USER_HOME` may select a cache location. Full-catalog checks are expensive and do not belong in every startup. Generated reports, caches/builds, nested sources and machine-local `.env.ps1` remain ignored. No server, database, start service or API key is needed for the research CLI.

Windows PowerShell and Git Bash setup/safeguards were executed during the fork transition; [recorded verification](../HANDOFF_VERIFICATION.md) links exact receipts. Historical Linux recovery and unexecuted macOS instructions do not establish a new platform pass. No hosted environment is claimed by this maintenance assignment; old creation/publication notes remain in [the historical archive](history/PRE_CONSOLIDATION_HANDOFF.md).
